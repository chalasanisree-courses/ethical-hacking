    Week 8 · System Attacks, Malware & Persistence¶

    🧭 Device · CEH: Maintaining Access & Covering Tracks · the routine you run on every host you land on, before moving to the next

    The loop — click a stage to jump

    1 Get in — credentials · code · config

    Three ways onto a host — the CCC — the same three you'll reuse to climb.

    🔑 Credentials

    Steal a key

    No exploit — just use a valid login. Steal a password, or phish a user into running your code as them. The quiet way.

    🐛 Code

    Exploit a bug

    All software has bugs. ShellShock was a Bash bug — not a web-server bug. Dirty COW, PrintNightmare are others. You land at the privilege of what you broke.

    ⚙️ Config

    Abuse a setting

    Nothing broken — a setting left too loose. User error is everywhere, so often the easiest path.

    What you become

    www-data, not root

    ShellShock lands you as the web server's low-privilege service account. Running code is initial access — climbing higher is a separate job.

    The machine you're climbing

    Every process runs as someone

    Boot starts systemd as root, which spawns everything else — each process tagged with an identity. Two axes: who it's for × how much power.

    Low privilege
    High privilege

    ordinary user — alice
    human admin — a sudoer

    2 Escalate — climb to root

    A shell runs at the privilege of whoever spawned it. So escalation means getting something already privileged to run your code. The config route — two mistakes combine:

    An operator can sudo-run a root script that's also writable.
    $ id uid=1001(operator) groups=operator,ops $ sudo -l (root) NOPASSWD: /opt/backup.sh mistake #1 → run this script as root $ ls -l /opt/backup.sh -rwxrwxr-x 1 root ops /opt/backup.sh mistake #2 → group 'ops' can write it, and we're in ops $ echo 'bash -i' >> /opt/backup.sh append one line: spawn a shell $ sudo /opt/backup.sh # whoami root sudo ran our edited script as root → root shell

    Attackers don't guess — LinPEAS / WinPEAS scan the box and list every opening of all three kinds (the same checks a privesc module carries).

    The defender's counter

    Least privilege

    Give each account only the power it needs — then a foothold or a found opening reaches almost nothing, and the climb stalls.

    3 Persist — keep the position, and the RAT

    Your foothold is fragile: a reboot, a dropped link, or a patch of the hole you came in through locks you out. So leave a way back in, at your elevated level.

    Your own way back

    Key to the door

    Create an admin/root account, or drop an SSH key in authorized_keys — log straight back in.

    Hook into startup

    Relaunch on boot

    🐧 a cron job or systemd service · 🪟 a registry Run key, scheduled task, or service — comes up with the legit ones.

    The defender's counter

    Patch first

    Patching closes the hole the exploit needs — the #1 control. It's because a patch can lock them out that attackers rush to persist. Defenders also hunt rogue Run keys/services and watch for beaconing.

    Staying hidden

    Stealth isn't a stage — it's a band under the whole loop. The host runs endpoint protection (EPP/EDR), and each evasion beats one of its checks.

    Beats the on-disk scan

    📦 Packing

    Scramble the file so signature AV matches nothing on its known-bad list. Same malware, new fingerprint.

    Beats the process watch

    🧬 Process hollowing

    Gut a trusted process like svchost and run your code inside it — looks legitimate.

    The arms race

    🛰️ EDR watches behavior

    Modern EDR ignores fingerprints and asks: is this process acting wrong? So malware stays under the radar.

    The ultimate evasion

    🫥 Rootkit

    AV/EDR trust what the OS reports. Compromise the OS itself and it lies for you — nothing left to detect. Stuxnet (2010) hid at kernel level for months.

    4 Steal credentials, then pivot

    Now you're root, the stored secrets are readable. Different from Stage 2: there you stole one key to go up; here you harvest all of them to go out — and it needs root, so it only works now.

    🐧 Linux

    /etc/shadow

    Grab the hashes you couldn't read before and crack the weak ones offline.

    🪟 Windows

    LSASS + Mimikatz

    Recent logins are cached in memory — Mimikatz scrapes them straight out.

    Often you don't even crack the hash — just replay it to authenticate elsewhere: pass-the-hash.

    The defender's counter

    Protect the credentials

    Credential Guard & LSASS protection wall off memory from Mimikatz; unique local-admin passwords stop one key opening the rest; MFA means a stolen password alone isn't enough.

    5 Act — exfiltrate, quietly

    Reaching the data is easy once you're a trusted admin. Getting it out is hard — a big transfer trips volume alerts and DLP. So the act is done under stealth.

    🐢 Low and slow

    No volume spike

    Trickle it out in small chunks over days, disguised as ordinary HTTPS and encrypted so inspection can't read it.

    🕳️ The clever channel

    DNS tunneling

    Hide data in DNS lookups — a protocol that's almost always allowed out and rarely inspected.

    Cover your tracks — the exit

    Different from stealth: that kept you unseen while operating; this is anti-forensics afterward — switch off the cameras and wipe the tape.

    🎥 Disable logging🧹 Clear logs — event, auth, shell history🕰️ Timestomp — fake file timestamps

    Two goals: buy time (the later they notice, the colder the trail), and defeat the forensic investigation — leave no evidence of how you got in, what you took, or who you are.

    Malware is this loop, automated

    Everything above, done by hand, is exactly what malware does on its own — modules assembled like any program.

    💣 Damage, not theft ›
    Not every attacker wants data. Ransomware encrypts files for a ransom; attacks on industrial and refrigeration control systems can manipulate physical equipment directly. When the goal is damage, the "act" looks different, but the routine to reach it is the same.

    The defender's view

    Because the attacker must walk this routine, the defender gets a control at every step — that's defense in depth.

    Get in / escalate

    Patch — the exploit fails · least privilege — a foothold can't climb

    Stay hidden

    EDR — catches behavior packing can't hide

    Steal creds

    Credential Guard · LAPS · MFA — nothing worth stealing

    Exfiltrate / cover tracks

    DLP · outbound monitoring · protected logs they can't erase

    The loop is the spine, stealth is the band, malware is the tooling — run on every host you reach.

    This week — put it into practice

    You'll run the loop two ways: by hand, then automated by a tool.

    Lab 1 · by hand

    Remote & Local Exploitation

    Exploit a vulnerable service on a Linux server with Metasploit → land a foothold → escalate to a privileged shell. Get in + climb, manually.

    Lab 2 · automated

    Deploy a RAT

    Recover the admin password → log in over RDP → deploy DarkComet for command-and-control. The same loop, now bundled into one tool.
